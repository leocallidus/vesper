# Shaderpacks (Шейдерпаки) — дизайн и поэтапный план

Документ описывает профессиональный план внедрения “Shaderpacks” в Vesper: импорт наборов шейдеров без перекомпиляции, каталогизация, предпросмотр и выбор внутри режима **“GLSL шейдер”**.

## 1) Цели и UX

### Цели
- Дать пользователю **простую библиотеку** шейдеров (как “пак”), которую можно переносить между ПК.
- Сделать импорт “как в Steam Workshop”: **перетаскивание папки** (и опционально `.zip`) в настройки.
- Не ломать текущий сценарий “выбрать один `.glsl` файл”.
- Прозрачная диагностика: какие файлы подхвачены (Image/Common/BufferA–D), предупреждения о multipass и аварийная клавиша закрытия.

### UX: новый раздел Settings → Shaderpacks
- При первом открытии: **пустое состояние** (Empty State)
  - большая подсказка: “Перетащите папку шейдерпака сюда…”
  - поддержка drag&drop файлов/папок на область подсказки
- После импорта:
  - список карточек/строк шейдерпаков: **лого + название + описание (≤350) + количество шейдеров**
  - кнопки: **Удалить**, **Открыть папку**, **Проверить** (валидация/список найденных шейдеров)
  - (опционально) “Включен/выключен” для временного скрытия в выборе контента

### UX: Settings → Content → “GLSL шейдер”
Добавить режим выбора в 2 шага, при этом оставить ручной путь:
- Переключатель источника:
  - **Файл/папка** (текущий способ)
  - **Shaderpack**
- Если выбран Shaderpack:
  - выпадающий список **Shaderpack**
  - выпадающий список **Shader** (шейдер внутри пака)
  - предпросмотр (опционально: мини-превью/скриншот, если будет)
  - кнопка **“Проверить шейдеры / показать найденные BufferA–D + Common”** (уже есть для пути — расширить под пак)

## 2) Формат шейдерпака (предложение)

### Структура папок
Шейдерпак — это папка (имя папки произвольное):
```
MyPack/
  shaderpack.toml
  shaderpacklogo.png
  shaders/
    Warped Offset Block Corridor/
      Common.glsl
      BufferA.glsl
      Image.glsl
    Bebra/
      Image.glsl
```

Правила:
- `shaderpack.toml` обязателен.
- `shaderpacklogo.png` обязателен (можно добавить fallback-иконку, если отсутствует).
- Внутри `shaders/` каждая подпапка = один шейдер (1..N).
- Внутри шейдера поддерживаются файлы: `Image.*`, `Common.*`, `BufferA..D.*` (`.glsl/.frag/.fs`).
- Максимум **5 пассов** (4 буфера + Image), как сейчас.

### manifest (TOML)
Файл: `shaderpack.toml`

Рекомендуемая схема:
```toml
schema_version = 1

[pack]
id = "retro-pack"                  # опционально; если нет — генерируется
name = "Retro Collection"
description = "Короткое описание до 350 символов..."
author = "Your Name"               # опционально
homepage = "https://..."           # опционально

# Опционально: общая лицензия пака (не заменяет лицензии отдельных шейдеров)
license = "CC-BY-4.0"

[[shader]]
id = "warped-corridor"             # опционально; если нет — генерируется из имени папки
name = "Warped Offset Block Corridor"
path = "shaders/Warped Offset Block Corridor"
description = "..."
source_url = "https://www.shadertoy.com/view/...."   # опционально
license = "CC BY 3.0"                               # опционально
author = "..."                                       # опционально
```

Валидация:
- `pack.name` обязателен.
- `pack.description` обрезается до 350 символов при отображении (оригинал можно хранить полностью).
- Если `[[shader]]` не задан — делаем автоскан `shaders/*/Image.*`.

## 3) Хранение и импорт

### Где хранить
Рекомендуемо (XDG):
- 'XDG_CONFIG_HOME/vesper/shaderpacks/<pack_id>/...'

### Импорт
Поддержать 2 варианта:
1) DnD папки (URI на директорию) → копировать в data-dir.
2) (Опционально) DnD `.zip` → распаковать в temp → импортировать.

### Обновление/конфликты
- Если `pack_id` уже существует:
  - диалог: “Заменить / Создать копию / Отмена”
- Генерация `pack_id`, если нет в TOML:
  - безопасный slug из `pack.name` + короткий хэш (например sha256 первых байт манифеста).

## 4) Движок исполнения (минимально меняем существующее)

Сейчас `ScreensaverMode::Shadertoy(String)` принимает путь к файлу/папке.

### План интеграции без большого рефакторинга
- При выборе шейдера из пака в конфиг записывать **реальный путь** к выбранному `Image.glsl` внутри data-dir.
- Это позволяет НЕ менять рендер-пайплайн сейчас: он уже умеет folder-based multipass рядом с `Image.*`.

Дальше (опционально) можно добавить “виртуальные” пути (`shaderpack://pack/shader`) и резолвить в рантайме, но это не обязательно в v1.

## 5) Безопасность и стабильность

Риски:
- пользовательские GLSL могут подвешивать GPU драйвер/процесс
- multipass может быть тяжелым

Меры (уже частично реализованы):
- предупреждение при multipass
- настраиваемая аварийная клавиша закрытия (“Принудительное закрытие”)
- (план) дополнительная защита:
  - лимит render-scale (например не выше 8192 и не ниже 16 уже есть)
  - таймаут на компиляцию/линковку (практически сложно; лучше “panic hotkey” + уведомление)

## 6) Поэтапный план внедрения (Milestones)

### Этап 1 — Формат + загрузчик (backend)
- Добавить модуль `shaderpacks`:
  - поиск `shaderpack.toml`, парсинг TOML (`toml` + `serde`)
  - валидация структуры, генерация `pack_id`/`shader_id`
  - скан шейдеров и обнаружение `Image/Common/BufferA–D`
- Добавить структуру данных:
  - `Shaderpack { id, name, description, logo_path, shaders: Vec<ShaderEntry> }`
  - `ShaderEntry { id, name, dir, detected_files... }`

### Этап 2 — Импорт/удаление (storage)
- Реализовать “ImportShaderpack”:
  - копирование папки в `XDG_DATA_HOME`
  - диалоги конфликтов
  - удаление (и очистка ссылок в конфиге, если выбран удаленный шейдер)

### Этап 3 — UI: Settings → Shaderpacks
- Добавить новую страницу/раздел:
  - Empty State с подсказкой + drop-target
  - список импортированных паков
  - карточка: лого/название/описание/кол-во шейдеров
  - кнопки: Удалить / Открыть / Проверить
- Полная i18n для RU/EN.

### Этап 4 — UI: выбор в “GLSL шейдер”
- Добавить selector источника (Файл/Shaderpack).
- Добавить 2 выпадающих списка:
  - Shaderpack (из списка импортированных)
  - Shader (из выбранного пака)
- При применении: записывать путь до `Image.*` выбранного шейдера в текущий `ScreensaverMode::Shadertoy(path)`.

### Этап 5 — Диагностика “Проверить шейдеры”
- Расширить существующую кнопку:
  - для shaderpack-выбора показывать, какие пассы найдены у выбранного шейдера
  - показывать `Common` и `BufferA–D` (уже запрошено)

### Этап 6 — Опциональные улучшения (v1.1+)
- Импорт `.zip` (библиотека `zip`).
- Встроенные текстуры для iChannel (если появится формат в паке `assets/`).
- Скриншоты/превью:
  - `preview.png` для каждого shader entry (вместо рендера в реальном времени в списке)
- Live reload при изменении файлов (watcher) — опционально.

## 7) Рекомендуемые зависимости (если понадобятся)
- `toml` + `serde` (парсинг манифеста)
- `walkdir` (сканирование директорий)
- `sha2` (генерация стабильных id/хэшей)
- `zip` (опционально, импорт архивов)

## 8) Открытые вопросы (чтобы зафиксировать до реализации)
1) Разрешаем ли хранить пак “по месту” (без копирования), или всегда импортируем в data-dir? Ответ: Нет, потому что если шейдерпак удалится "по месту" то его не будет, лучше переместить его в отдельную папку. В самой программе можно будет удалить шейдерпак или из директории.
2) Нужна ли поддержка текстур/кубмапов в iChannel из shaderpack (assets)? Ответ: Да, обязательно
3) Нужен ли экспорт shaderpack обратно в `.zip` из UI? ответ: Да
4) Делаем ли отдельные лицензии/атрибуцию обязательными (для Shadertoy CC)? Ответ: Нет
